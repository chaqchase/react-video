Calls one function with an event each time something happens in playback. Play, seek, and pause the demo, and watch the events appear under it.

<Demo slug="analytics" />

## Usage

```tsx
import { analytics } from "react-video-kit/analytics";
import { VideoPlayer } from "react-video-kit/player";

const plugins = [analytics({ onEvent: (event) => console.log(event) })];

<VideoPlayer src="/video.mp4" plugins={plugins} />;
```

`heartbeat` sets the seconds of playback between `heartbeat` events, and defaults to 30. `0` turns them off:

```tsx
analytics({ onEvent: (event) => console.log(event), heartbeat: 10 });
```

## Send events to a service

```tsx
analytics({
  onEvent(event) {
    navigator.sendBeacon("/api/video-events", JSON.stringify(event));
  },
});
```

## Events

| `type` | When it fires | Extra field |
| --- | --- | --- |
| `load` | A source starts loading. | |
| `ready` | The source moves from loading to ready. | `startupMs` |
| `play` | Playback starts or resumes. | |
| `pause` | Playback pauses, except when the video ended. | |
| `seek` | A seek finishes. | |
| `rebuffer-start` | Playback stalls after it has started, while not paused or recovering from a seek. | |
| `rebuffer-end` | That stall stops, including because the viewer paused or started a seek. | `stalledMs` |
| `quality-change` | The active quality level changes to a known one. | `quality` |
| `ended` | The video ends. | |
| `error` | A new error appears, fatal or not. | `error` |
| `heartbeat` | Every `heartbeat` seconds of video played. | |

Every event has `type`, `position`, and `source`.

## Behaviour

- Heartbeats count video played. Seeks and source changes add nothing and don't reset the count, so adding heartbeats up gives a close measure of how much was watched. It counts video time, so playing at 2× reaches the next heartbeat twice as fast.
- `position` comes from the player's clock when the event is sent, so `seek` reports where the seek landed.
- Dragging the timeline can send several `seek` events, one for each seek that finishes.
- A stall caused by a seek isn't counted as a rebuffer, including the moment after the seek finishes while playback picks back up.
- The end of the video sends `ended` without a `pause`.
- `onEvent` runs inside the player's store update. Keep it quick, and don't let it throw, because that would stop the other subscribers in that update.
